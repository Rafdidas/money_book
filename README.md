# Money Book

https://monibuk.com/

## 왜 만들었나

Money Book은 월급, 카드 지출, 저축, 투자 매수를 한 화면에서 빠르게 확인하려고 만든
한국어 개인 재무 웹 앱입니다. 기존 가계부는 기록 자체에는 충실하지만, 월말에
"이번 달에 얼마가 남았고 어디에서 흐름이 바뀌었는지"를 다시 계산해야 하는 일이
많았습니다.

그래서 대시보드는 월별 수입·지출·잔액과 최근 내역을 빠르게 확인하는 데 집중하고,
카테고리 분석, 전월 비교, 현금 흐름 해석처럼 생각할 거리가 많은 기능은 분석
화면으로 분리했습니다. 로그인 없이도 데모 데이터를 바로 체험할 수 있게 만들어
첫 진입 장벽도 낮췄습니다.

## 배포 링크

- 서비스: https://monibuk.com/
- 데모: 로그인 화면의 `데모 체험하기`로 바로 사용 가능

## 문제와 해결

### 1. 기록은 쉬워야 하지만, 월별 상태는 바로 보여야 했습니다

수입과 지출을 입력하면 월별 합계, 잔액, 전월 대비 변화율, 일별 누적 흐름,
카테고리별 지출 비율, 월간 캘린더가 같은 데이터에서 함께 갱신되도록 구성했습니다.
공통 데이터 타입을 기준으로 화면별 파생 값을 만들고, 복잡한 해석은 분석 화면에
배치해 모바일에서도 핵심 금액을 hover 없이 읽을 수 있게 했습니다.

### 2. 개인 재무 데이터는 사용자별로 완전히 분리되어야 했습니다

Supabase Auth로 로그인 사용자를 식별하고, 지출·저축·고정지출·투자·문의 테이블에
RLS 정책을 적용했습니다. 데모 모드는 Supabase에 쓰지 않고 브라우저 `localStorage`
에만 저장해 실제 사용자 데이터와 샘플 데이터를 분리했습니다.

### 3. 국내 주식 검색과 종가 조회는 외부 API 제약을 흡수해야 했습니다

투자 화면에서는 한국투자증권의 KOSPI/KOSDAQ 종목 마스터 파일을 서버에서 읽어
종목 검색에 사용합니다. 종목 마스터는 12시간 캐시하고, 금융위원회 공공데이터 API로
가져온 최근 종가는 6시간 캐시합니다. 종가 조회는 한 요청당 20개 종목, 5개 동시
조회, 사용자당 분당 30개 배치 요청으로 제한해 외부 API 호출량과 사용자 경험을
함께 관리했습니다.

## 결과 수치

- 실제 배포 URL 1개와 로그인 없는 데모 모드 제공
- App Router 기준 사용자 화면 11개 구성
- 서버 API 2개 제공: 종목 검색, 최근 종가 조회
- Supabase 마이그레이션 7개로 가계부, 저축, 고정지출, 투자, 문의, RLS 정책 관리
- 종목 검색 결과 최대 12개 반환
- 종목 마스터 캐시 12시간, 종가 캐시 6시간 적용
- 최근 종가 조회 한 요청 최대 20개, 동시 조회 5개, 사용자당 분당 30개 배치 요청 제한

## 주요 기능

- 이메일 기반 회원가입, 로그인, 인증 콜백 처리
- 로그인 없는 데모 모드
- 수입/지출 내역 추가, 수정, 삭제
- 월별 수입, 지출, 잔액, 전월 대비 변화율 확인
- 일별 누적 흐름 차트와 카테고리별 지출 비율 차트
- 월간 캘린더와 선택 날짜별 내역 확인
- 월별 분석 화면의 카테고리 분석, 비교, 현금 흐름 해석
- 투자 매수 기록, 국내 종목 검색, 최근 종가 조회
- ISA·연금저축 연도별 한도 관리
- 문의 등록 화면과 사용자별 데이터 접근 제한

## 어떻게 구현했나

Next.js App Router는 공개 인트로, 인증, 앱 내부 화면, 서버 API를 경로 단위로
나누는 데 사용했습니다. 대시보드와 분석 화면은 같은 가계부 데이터를 공유하되,
대시보드는 빠른 상태 확인, 분석 화면은 상세 해석이라는 역할을 다르게 가져갑니다.

React 컴포넌트는 입력 폼, 캘린더, 차트, 사이드 메뉴처럼 재사용되는 단위로 분리했고,
월별 요약처럼 여러 화면에서 쓰이는 계산은 렌더링 코드 밖으로 빼서 다루었습니다.
Chart.js는 표준 라인·파이 차트에 사용하고, 금융 흐름처럼 앱 맥락에 맞춘 시각화는
커스텀 SVG로 처리해 불필요한 시각화 의존성을 늘리지 않았습니다.

Supabase는 인증, 데이터 저장, RLS 정책에 사용했습니다. 클라이언트에서 사용자별
데이터를 다루되, 테이블 정책으로도 `auth.uid()` 기준 접근을 제한해 화면 실수만으로
다른 사용자 데이터가 노출되지 않게 했습니다.

국내 주식 기능은 서버 라우트에서 외부 데이터를 중계합니다. KIS 종목 마스터는
EUC-KR로 인코딩된 압축 파일을 해제해 검색 가능한 형태로 정규화하고, 공공데이터
종가 조회는 서버 캐시와 Supabase RPC 기반 rate limit을 함께 사용해 호출 실패와
과도한 요청을 줄였습니다.

## 트러블슈팅 기록

### KOSPI/KOSDAQ 종목 마스터 인코딩과 압축 처리

종목 마스터 파일은 일반 JSON API가 아니라 압축된 고정폭 텍스트 파일이었습니다.
브라우저에서 처리하지 않고 서버에서 zip 데이터를 해제한 뒤 EUC-KR로 디코딩하고,
시장별로 다른 종목명 오프셋을 적용했습니다. 이후 종목명, 종목코드, 영문명이 섞인
검색어를 정규화해 코드 일치, 이름 완전 일치, prefix, 포함 순서로 점수를 매겨
검색 품질을 보정했습니다.

### 외부 종가 API 호출량 제어

투자 화면에서 여러 종목을 한 번에 갱신하면 외부 API 호출이 급증할 수 있었습니다.
이를 해결하기 위해 서버 API에서 중복 종목을 제거하고, 요청당 20개 제한과 5개 동시
조회 배치를 적용했습니다. 같은 종목은 6시간 동안 서버 캐시를 재사용하고, 사용자별
분당 30회 제한은 Supabase RPC로 관리해 배포 환경이 여러 인스턴스로 늘어나도 같은
기준을 유지하도록 했습니다.

### 데모 모드와 실제 데이터 분리

포트폴리오 방문자가 회원가입 전에 앱을 확인할 수 있어야 했지만, 데모 데이터가
실제 DB에 섞이면 안 됐습니다. 데모 모드에서는 샘플 데이터를 브라우저 `localStorage`
에 저장하고, 로그인 사용자의 데이터만 Supabase에 저장하도록 분기했습니다. 덕분에
실제 배포 링크에서 기능을 보여주면서도 사용자별 RLS 정책은 그대로 유지할 수
있습니다.

## 로컬 실행

```bash
npm install
npm run dev
```

프로젝트 루트에 `.env.local`을 만들고 Supabase와 공공데이터 API 키를 등록합니다.

```env
NEXT_PUBLIC_SUPABASE_URL=your-supabase-url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-supabase-anon-key
FSC_STOCK_SERVICE_KEY=your-fsc-stock-service-key
FSC_SECURITIES_PRODUCT_SERVICE_KEY=your-fsc-securities-product-service-key
```

브라우저에서 `http://localhost:3000`을 열어 확인합니다.

## 데이터베이스

초기 지출 테이블은 아래 형태로 시작합니다.

```sql
create table public.expenses (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  amount numeric not null,
  type text not null check (type in ('income', 'expense')),
  category text not null,
  memo text not null default '',
  date date not null,
  created_at timestamptz not null default now()
);
```

RLS와 추가 테이블은 `supabase/migrations/`의 마이그레이션에 포함되어 있습니다.
Supabase CLI를 사용한다면 마이그레이션을 적용하고, CLI를 사용하지 않는다면 해당
SQL을 Supabase SQL Editor에서 실행합니다.

## 프로젝트 구조

```text

  app/        # App Router 화면, 레이아웃, 서버 API
  components/ # 공통 UI와 차트 컴포넌트
  lib/        # Supabase, 외부 API, 데이터 처리 로직
  styles/     # 공통 스타일
  types/      # 공통 타입
  utils/      # 정규화와 포맷팅 유틸
supabase/
  migrations/ # 테이블, RLS, RPC 마이그레이션
```
