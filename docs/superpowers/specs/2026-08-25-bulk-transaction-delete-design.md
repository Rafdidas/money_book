# 거래 다중 선택·일괄 삭제 설계

## 배경

사용자가 적금 관리 기능을 찾지 못해 저축 내역을 직접 여러 건 입력했고, 이를
정리하려 해도 한 건씩만 삭제할 수 있다는 의견을 보냈다. 현재 홈의 `상세내용`
표는 선택한 월의 내역을 모두 보여주지만 읽기 전용이며, 직접 입력 내역 삭제는
`내역 추가/수정`의 수정 모드에서 한 건씩만 가능하다.

백엔드에는 이미 여러 ID를 사용자 범위로 삭제하는 `deleteExpenses(ids)`가 있다.
따라서 이번 작업은 새 테이블이나 마이그레이션을 만들지 않고, 삭제 가능한 항목을
안전하게 구분하는 선택 UI와 확인 흐름을 추가한다.

## 목표

- 선택한 월의 상세 내역에서 여러 직접 입력 거래를 한 번에 삭제한다.
- 직접 입력한 지출·수입·저축·투자를 모두 같은 방식으로 선택할 수 있게 한다.
- 적금·고정지출 규칙에서 생성된 납입과 일시정지 내역은 일괄 삭제에서 보호한다.
- 데스크톱과 모바일에서 선택 건수와 합계를 hover 없이 확인할 수 있게 한다.

## 범위 밖

- 적금 계좌, 고정지출 규칙 또는 미래 예정 내역 자체를 일괄 삭제하지 않는다.
- 필터, 검색, 페이지네이션 또는 여러 달을 아우르는 전체 선택은 추가하지 않는다.
- 삭제 취소, 휴지통 또는 soft delete를 도입하지 않는다.
- API, Supabase 스키마 및 RLS 정책을 변경하지 않는다.
- 카테고리 관리와 카드 실적 기능은 각각 별도 작업으로 진행한다.

## 삭제 가능 판정

상세 표는 `displayMonthlyExpenses`를 사용하므로 직접 입력 거래 외에 저장된 적금
납입, 고정지출 납입, 일시정지된 항목도 포함한다. 반면 기존
`monthlyEditableExpenses`는 다음 항목을 제외하고 있어 이번 기능의 삭제 가능
목록으로 재사용하기 적합하다.

- `storedPaymentIds`에 포함된 적금·고정지출 납입
- 레거시 적금 메타데이터가 담긴 거래
- 레거시 고정지출 메타데이터가 담긴 거래
- 활성 목록에서 이미 제외된 일시정지 거래

따라서 `monthlyEditableExpenses`의 ID 집합에 포함되는 상세 행만 선택 가능하게
한다. `entry_type: "savings"`인 직접 입력 저축은 이 집합에 남기 때문에 사용자가
잘못 입력한 저축 내역도 일괄 정리할 수 있다.

## 사용자 흐름

### 개별 선택

`상세내용` 표의 첫 열에 체크박스를 추가한다. 선택 가능한 행에는 거래의
카테고리와 날짜를 포함한 접근성 라벨을 제공한다. 정기 납입 또는 일시정지 행의
체크박스는 비활성화하고, 접근성 라벨로 `정기 항목은 해당 관리 메뉴에서
변경해주세요`라고 안내한다.

### 전체 선택

표 머리글 체크박스는 현재 월에 표시된 **선택 가능한 항목만** 선택한다.

- 선택 가능한 항목이 없으면 비활성화한다.
- 일부만 선택됐으면 `indeterminate` 상태를 표시한다.
- 모두 선택된 상태에서 다시 누르면 전체 선택을 해제한다.
- 정렬 순서는 선택 결과에 영향을 주지 않는다.

프로젝트의 공용 `Checkbox`가 이미 `indeterminate`와 44px 모바일 조작 영역을
지원하므로 이를 재사용한다.

### 선택 작업 바

한 건 이상 선택하면 표 아래에 작업 바를 표시한다.

- 문구: `{N}건 선택 · 합계 {금액}`
- 보조 버튼: `선택 해제`
- 위험 버튼: `선택 삭제`
- 삭제 요청 중에는 버튼을 비활성화하고 `삭제 중...`을 표시한다.

데스크톱에서는 상세 카드 아래쪽에 sticky로 유지한다. 모바일에서는 하단 내비게이션을
가리지 않도록 안전 영역과 내비게이션 높이 위에 고정한다. 핵심 값은 hover 없이
항상 보인다.

### 삭제 확인과 결과

`useAppAlert`의 기존 `confirm`을 사용한다.

- 제목: `선택한 내역 {N}건을 삭제할까요?`
- 설명: `합계 {금액}의 내역이 삭제됩니다. 이 작업은 되돌릴 수 없습니다.`
- 확인: `삭제`
- 취소: `취소`

확인 후 로그인 사용자는 `deleteExpenses(ids)`를 한 번 호출한다. 성공한 경우에만
로컬 `expenses` 상태에서 동일 ID들을 제거한다. 데모 사용자는 먼저 다음 목록을
`writeDemoExpenses`로 저장한 뒤 상태를 갱신한다. 저장 또는 삭제가 실패하면 현재
화면과 선택 상태를 유지하고 한국어 오류 알림을 표시해 재시도할 수 있게 한다.

삭제한 항목 중 현재 수정 폼에서 선택 중인 항목이 있으면 수정 선택을 해제하고
추가 모드로 되돌린다. 성공 후에는 전체 선택을 비운다. 사용자가 월을 변경하거나
선택 가능 목록에서 사라진 항목이 생긴 경우에도 유효하지 않은 선택 ID를 제거한다.

## 코드 구조

- `src/app/_home/detailBulkDelete.ts`
  - 선택 가능 ID 계산, 유효한 선택 정리, 선택 건수·합계 계산을 담당하는 순수 함수
- `src/app/_home/detailBulkDelete.test.ts`
  - 직접 입력/정기 항목 구분과 합계 계산 단위 테스트
- `src/app/_home/DetailBulkActionBar.tsx`
  - 선택 요약, 선택 해제, 삭제 버튼만 렌더링하는 작은 표현 컴포넌트
- `src/app/_home/DetailBulkActionBar.test.tsx`
  - 한국어 문구, 콜백, 삭제 중 상태 컴포넌트 테스트
- `src/app/_home/HomeClient.tsx`
  - 선택 상태, 전체/개별 선택, 확인창, 실제 삭제 및 표 체크박스 연결
- `src/app/page.scss`
  - 체크박스 열, 스크린리더 라벨, 반응형 sticky 작업 바 스타일

`HomeClient.tsx` 전체를 구조 변경하지 않는다. 선택 계산만 순수 함수로 분리하고
작업 바만 별도 컴포넌트로 빼서 기존 대형 컴포넌트에 추가되는 책임을 제한한다.

## 접근성

- 모든 체크박스는 텍스트 접근성 라벨을 가진다.
- 전체 선택은 선택 없음, 일부 선택, 전체 선택 상태를 네이티브 checkbox와
  `indeterminate`로 전달한다.
- 삭제 버튼은 색상만이 아니라 `선택 삭제` 문구로 위험 동작을 설명한다.
- 키보드로 행 선택, 전체 선택, 선택 해제, 삭제 확인까지 수행할 수 있어야 한다.
- 모바일 조작 대상은 최소 44px을 유지한다.

## 테스트 및 검증

단위·컴포넌트 테스트:

- 선택 가능한 ID만 전체 선택 대상이 되는지 확인
- 사라진 항목 ID가 선택에서 제거되는지 확인
- 선택 건수와 합계가 정확한지 확인
- 작업 바 버튼과 삭제 중 상태 확인
- 기존 `deleteExpenses(ids)`가 빈 배열을 무시하고 사용자 ID 범위에서 한 번에
  삭제한다는 기존 동작 유지

수동 브라우저 검증:

- 데스크톱 1280px와 모바일 390px
- 직접 입력 지출·수입·저축·투자의 개별 및 전체 선택
- 적금·고정지출 납입과 일시정지 항목의 비활성 상태
- 취소 시 데이터와 선택 유지
- 성공 시 선택 행만 사라지고 월 합계가 갱신됨
- 데모 모드 새로고침 후에도 삭제 결과 유지
- 가로 넘침, 하단 내비게이션 겹침, 키보드 포커스 확인

최종 검증 명령은 `npm test`, `npm run lint`, `npm run build`다.
