현재 `layout.tsx`는 jsdelivr의 **동적 서브셋(dynamic-subset)** 스타일시트를 사용한다. 한글 글리프가 여러 woff2 조각으로 나뉘어 필요한 것만 지연 로드되는 방식이므로, 이를 단일 로컬 폰트 파일로 바꾸면 초기 전송량이 크게 늘어난다. 따라서 로컬 전환은 서브셋 조각 구조를 유지한 채 `public/` 이하에서 제공하거나 `next/font/local`로 감싸는 방식으로 진행하고, 전환 전후의 초기 폰트 전송량을 비교해 회귀가 없음을 확인한다.

CDN 제거는 CSP 헤더 변경을 동반한다. `next.config.ts`의 `style-src`와 `font-src`에 있는 `https://cdn.jsdelivr.net` 출처를 함께 제거하고, `next.config.test.ts`가 이 변경과 일치하도록 갱신한다.

## 회원가입 및 동의 이력

### 화면 동작

회원가입 폼에 다음 항목을 추가한다.

1. 전체 동의(편의 기능)
2. `[필수] 만 14세 이상입니다`
3. `[필수] 이용약관에 동의합니다`
4. `[필수] 개인정보 수집·이용에 동의합니다`

이용약관과 개인정보처리방침의 제목은 해당 공개 문서로 연결한다. 전체 동의는 세 필수 항목을 함께 변경하며, 개별 항목 변경 시 전체 동의 상태와 부분 선택 상태를 동기화한다.

필수 항목이 누락된 제출은 Supabase 요청 전에 차단한다. 첫 누락 항목에 오류 메시지를 표시하고 포커스를 이동해 키보드와 보조기기 사용자가 원인을 알 수 있게 한다.

### 서버 기록과 강제 규칙

`profiles`에 다음 열을 추가한다. 이 열은 현재 유효한 동의 상태를 빠르게 판정하기 위한 요약값이며, 기존 행에는 `NULL`로 추가한다.

- `terms_version`, `terms_agreed_at`
- `privacy_version`, `privacy_agreed_at`
- `age_confirmed_at`
별도로 `user_legal_consents` 이력 테이블을 추가한다. 각 행은 사용자 ID, 약관 버전, 개인정보처리방침 버전, 만 14세 확인 시각, 서버 기록 시각을 보관한다. 사용자는 자신의 이력만 조회할 수 있고, INSERT·UPDATE·DELETE 권한은 부여하지 않는다. `profiles`의 요약 열 갱신과 이력 행 추가는 같은 트랜잭션에서 수행한다.

`profiles`에는 INSERT·UPDATE RLS 정책이 없고 트리거만 `security definer`로 기록하므로, 클라이언트가 이 열들을 직접 위조할 수 없다. 동의 이력을 이 테이블에 두는 근거가 여기에 있다.

가입 요청은 현재 문서 버전과 필수 동의 플래그를 Supabase 사용자 메타데이터로 전달한다.

#### 기존 트리거의 확장

새 트리거를 추가하지 않고, 이미 존재하는 `public.handle_new_user_profile()`을 `create or replace`로 확장한다. 트리거를 둘로 나누면 같은 테이블에 대한 발화 순서에 의존하게 되므로 단일 함수를 유지한다.

이 트리거는 `after insert **or update of email**`로 선언되어 있다. 따라서 동의 검증 로직은 반드시 `TG_OP = 'INSERT'` 조건 안에서만 실행한다. 이 조건이 없으면 기존 가입자의 이메일 변경 UPDATE가 동의 메타데이터 부재로 실패하게 된다.

확장된 함수가 보장하는 동작은 다음과 같다.

- `TG_OP = 'INSERT'`인 경우에만 현재 버전의 약관·개인정보 동의와 만 14세 이상 확인을 요구하고, 없으면 예외를 발생시켜 사용자 생성을 롤백한다.
- 유효한 신규 가입이면 데이터베이스 서버 시각(`now()`)으로 동의 일시를 `profiles`와 `user_legal_consents`에 함께 기록한다. 클라이언트가 보낸 시각은 신뢰하지 않는다.
- `TG_OP = 'UPDATE'`인 이메일 변경 경로는 기존과 동일하게 프로필 이메일만 갱신하고 동의 열은 건드리지 않는다.

#### 이 트리거가 보장하는 것과 보장하지 않는 것

`supabase.auth.signUp({ options: { data } })`로 전달한 값은 그대로 `auth.users.raw_user_meta_data`에 저장되며, 이 값은 **클라이언트가 완전히 통제한다.** 즉 가입 요청을 직접 작성하면 동의 플래그를 임의로 채워 넣을 수 있으므로, 이 트리거는 악의적 우회를 막는 보안 경계가 아니다.

트리거의 실제 가치는 두 가지다.

1. 화면 검증만 통과하고 서버에 동의 기록이 남지 않는 **불일치 상태를 구조적으로 차단**한다. 동의 열이 비어 있는 셀프 가입 계정은 존재할 수 없다.
2. 분쟁 시 제출 시점의 **동의 문서 버전과 서버 기준 시각**을 입증 자료로 보관한다.

실질적인 우회 방지가 필요해지면 service role로 가입을 처리하는 서버 라우트가 필요하지만, 이는 본 설계의 범위를 벗어나므로 채택하지 않는다.

### 기존 가입자 재동의

기존 가입자도 로그인 성공 시 재동의 대상에 포함한다. 현재 약관 또는 개인정보처리방침 버전이 `profiles`의 값과 다르거나, 두 동의 시각 또는 연령 확인 시각이 없으면 **재동의 필요** 상태다. 이번 마이그레이션으로 추가되는 열이 기존 계정에서 모두 `NULL`이므로, 기존 27명은 다음 로그인에서 모두 이 상태가 된다.

로그인 성공 뒤와 이미 로그인된 사용자가 `/app` 경로에 직접 진입할 때, 공통 동의 상태 조회 함수를 실행한다.

1. 현재 버전과 일치하면 기존처럼 `/app`으로 이동한다.
2. 재동의가 필요하면 `/auth/consent`로 이동시키며, 앱 경로의 데이터 조회·렌더링 완료 처리는 진행하지 않는다.
3. `/auth/consent`는 이용약관·개인정보처리방침 링크와 `[필수] 만 14세 이상`, `[필수] 이용약관 동의`, `[필수] 개인정보 수집·이용 동의`를 제공한다. 세 항목을 모두 선택한 `동의하고 계속하기`만 앱 진입을 허용한다. 거부 시 선택 가능한 동작은 로그아웃뿐이다.
4. 데모 모드는 서비스 회원이 아니므로 이 검사를 적용하지 않는다.

동의 제출은 인증된 사용자가 호출할 수 있는 `record_current_legal_consent()` 보안 정의 RPC로 처리한다. 이 함수는 `auth.uid()`만 대상으로 하고, 클라이언트가 전달한 버전·시각을 받지 않는다. 마이그레이션에 고정한 현재 문서 버전과 DB 서버의 `now()`를 사용해 `profiles` 요약값을 갱신하고 `user_legal_consents`에 새 행을 추가한다. 앱의 `src/lib/legal/` 상수와 RPC의 버전 문자열은 같은 배포에서 일치해야 하며, 문서 버전 변경 때마다 새 마이그레이션으로 RPC를 교체한다.

이 흐름은 인증 자체를 막지는 않지만, 재동의 전에는 앱 기능에 도달할 수 없게 한다. `/auth/consent` 외의 인증 화면에서 이미 로그인된 사용자를 자동 이동시킬 때도 같은 판정 함수를 사용해 재동의 화면을 건너뛰지 않게 한다.

#### 거부 시 사용자 대응

트리거가 예외를 발생시키면 Supabase는 `Database error saving new user` 형태의 원문 오류를 반환한다. 현재 `signup/page.tsx`의 `getSignupErrorMessage`는 매칭되지 않은 메시지를 그대로 `alert`에 노출하므로, 이 케이스에 대한 한국어 문구 매핑을 추가한다. 정상 경로에서는 화면 검증이 먼저 차단하므로 이 메시지는 비정상 요청에만 노출된다.

#### 관리자 계정 생성 절차

동의 메타데이터가 없는 사용자 생성이 거부되므로, Supabase 대시보드에서 계정을 수동 생성한 뒤 `profiles.role`을 승격하던 기존 절차는 더 이상 동작하지 않는다.

**결정: 거부 규칙을 유지하고, 관리자 계정도 일반 회원가입 화면을 거쳐 만든 뒤 `role`만 승격한다.** 관리자 역시 서비스 이용자이므로 동의 기록이 남는 편이 자연스럽고, 트리거에 예외 통로를 두면 그 통로가 곧 우회 경로가 되기 때문이다. 코드 변경 없이 운영 절차만 바뀐다.

향후 OAuth 로그인을 도입하면 OAuth 신규 가입에는 이 메타데이터가 없어 동일한 문제가 발생한다. 그 시점에 동의 수집 화면을 가입 흐름 안에 배치하는 방식으로 재설계해야 하며, 본 설계의 범위에는 포함하지 않는다.

## 분석 동의 — 채택하지 않음 (2026-08-06 결정)

초안은 `AnalyticsConsent` 배너로 Google Analytics, Vercel Analytics, Speed Insights를 사전 동의 뒤로 게이팅하려 했다. **이 항목은 구현하지 않기로 결정했다.** 세 도구는 현재대로 동의 없이 로드한다.

### 근거

- **법적 의무가 아니다.** 「개인정보 보호법」 제30조 제1항 제7호가 요구하는 것은 자동 수집 장치의 설치·운영과 **거부에 관한 사항**을 처리방침에 기재하는 것이다. 사전 동의(opt-in)를 강제하지 않는다. 공개한 처리방침 제10절이 사용 도구, 수집 항목, 브라우저 설정과 차단 도구를 통한 거부 방법을 이미 기재하고 있어 요건을 충족한다. 초안이 이를 미비점으로 다룬 것은 과한 판단이었다.
- **실제로 쓰는 데이터를 잃는다.** 운영자가 GA 대시보드를 주기적으로 확인하고 있다. 현재 사용자 27명 규모에서 동의율만큼 표본이 줄면 GA와 Speed Insights 모두 판단 근거로 쓰기 어려워진다. 법적으로 요구되지 않는 상향 조치를 위해 실사용 중인 데이터를 희생하는 교환은 성립하지 않는다.

### 다시 검토해야 할 조건

- EU·EEA 방문자가 의미 있는 규모로 발생하는 경우. GDPR 및 ePrivacy는 분석 쿠키에 사전 동의를 요구하므로 그때는 배너가 필요하다.
- 사용자 규모가 커져 표본 손실을 감당할 수 있게 되는 경우.

재개할 경우 필요한 구현은 다음과 같다. 하단 배너에서 동의·거부를 같은 비중으로 제공하고, 동의 전에는 세 도구를 렌더링하지 않으며, 철회 시 `window['ga-disable-G-EKPQWDNXFQ'] = true`로 현재 세션 전송을 중단하고 `_ga` 계열 쿠키를 삭제한다. 이미 로드된 gtag는 언마운트만으로 멈추지 않으므로 이 플래그가 필요하다.

## 약관의 투자정보 및 책임 제한

투자 화면의 시세·종목 정보는 정보 제공과 기록 보조 목적이며, 매수·매도 또는 특정 금융상품에 대한 권유가 아님을 명시한다. 시세의 정확성, 완전성, 실시간성 및 이용자의 투자 손익을 보장하지 않으며 투자 판단과 결과는 이용자에게 귀속된다.

서비스는 무료 개인 가계부로서 기능을 변경·중단할 수 있고, 이용자는 중요한 기록을 별도로 백업해야 한다. 다만 고의·중과실 또는 법률상 배제할 수 없는 책임을 면제하는 표현은 사용하지 않는다.

## 구현 범위와 비범위

포함:

- 법적 공개 페이지와 메타데이터
- 재사용 법적 링크(인트로 푸터, 사이드 메뉴, 모바일 드로어)
- 회원가입 필수 동의 UX와 프로필 동의 이력 마이그레이션
- 기존 가입자 로그인 재동의 화면·앱 경로 접근 제어·동의 기록 RPC
- `sitemap.ts`에 법적 문서 URL 추가
- 단위 테스트, 데스크톱·모바일 시각 검증, `HANDOFF.md` 갱신

포함하지 않음:

- 운영 Supabase 데이터베이스에 마이그레이션을 직접 적용하는 작업
- 배포 작업
- 별도 회원 탈퇴 UI
- service role 기반 서버 가입 라우트
- OAuth 로그인 사용자의 동의 수집 흐름
- 선택형 분석 동의 배너 (2026-08-06 미채택 결정)
- 외부 폰트 CDN 제거와 CSP 정리 (2026-08-06 보류)
- 법률 자문 또는 법률 적합성 보증

## 검증 기준

1. 법적 페이지가 비로그인 상태에서 열리고 정확한 운영자·연락처·시행일을 표시한다.
2. 모든 필수 동의가 있어야만 회원가입 요청이 전송된다. 누락 시 첫 미동의 항목으로 포커스가 이동한다.
3. 신규 가입 시 동의 버전과 **서버 기준** 동의 시각이 `profiles`에 기록된다. 클라이언트가 보낸 시각은 저장되지 않는다.
4. 동의 메타데이터가 없는 가입 요청은 거부되고, 사용자에게는 DB 원문 오류가 아닌 한국어 문구가 표시된다.
5. 기존 가입자의 **이메일 변경 UPDATE가 동의 검증에 걸리지 않고** 성공한다. 이 경로에서 동의 열은 변경되지 않는다.
6. 동의 열이 없는 기존 가입자는 로그인 후 `/auth/consent`로 이동하고, 동의 전에는 `/app`에 직접 진입할 수 없다.
7. 기존 가입자가 세 필수 항목에 동의하면 서버 시각과 현재 문서 버전으로 `profiles`와 `user_legal_consents`가 함께 기록되고 `/app`으로 이동한다.
8. 현재 버전으로 동의한 사용자는 이후 로그인에서 재동의 화면을 거치지 않는다. 문서 버전을 올리면 다음 로그인에서 다시 재동의 대상이 된다.
9. 처리방침 제10절이 실제로 로드되는 분석 도구와 그 거부 방법을 사실대로 기재한다.
10. `/legal/privacy`와 `/legal/terms`가 `sitemap.xml`에 포함되고 `robots.txt`에 차단되지 않는다.
11. 비로그인 방문자가 인트로 화면에서, 로그인 사용자가 사이드 메뉴와 모바일 드로어에서 두 문서로 이동할 수 있다.
12. 데스크톱과 모바일에서 문서, 가입 동의 영역, 재동의 화면을 읽고 조작할 수 있다.
13. `npm test`, `npm run lint`, `npm run build`를 통과한다.

4·5번은 로컬 Supabase에서 마이그레이션을 적용해 확인한다. 운영 DB 반영은 범위에 포함하지 않는다.

## 자체 검토

- **자리표시자:** 없음. 운영자, 이메일, 리전, 보유 기간, 시행일이 확정되어 있다.
- **일관성:** 처리방침 제10절의 분석 도구 고지는 사전 동의를 두지 않는 실제 동작과 일치한다. CSP 보고 보유 기간은 실제 정리 작업 주기를 인용한다. 가입·재동의는 모두 서버 시각과 문서 버전을 기록하며, 재동의 전 앱 경로 접근을 차단한다.
- **범위:** 회원 탈퇴 UI, 운영 DB 반영·배포, service role 가입 라우트, OAuth 동의 흐름은 명시적으로 제외해 단일 구현 계획으로 관리한다.
- **모호성 해소:** Supabase의 주 데이터 저장 위치는 서울이며, Vercel과 Supabase 지원·운영 과정의 국외 처리는 정책에 별도 고지한다. 투자 개인 기록은 외부 시세 API로 전송하지 않는다.

### 검토에서 조정한 판단

- **트리거의 성격:** 초안은 트리거가 화면 검증 우회를 막는다고 기술했으나, 가입 메타데이터는 클라이언트가 통제하므로 사실과 다르다. 보안 경계가 아닌 **동의 이력 보관 장치**로 성격을 정정했다.
- **관리자 계정:** 거부 규칙에 예외를 두는 대신 관리자도 일반 가입 흐름을 거치도록 운영 절차를 바꿨다. 예외 통로가 곧 우회 경로가 되는 것을 피하기 위한 선택이다.
- **기존 트리거 재사용:** 초안은 트리거 추가와 기존 흐름 유지를 동시에 요구했으나 두 요구가 충돌할 수 있어, 기존 함수 확장과 `TG_OP` 분기를 구현 조건으로 명시했다.

### 남은 위험

- Supabase와 Vercel의 국외 처리 서술은 공개 문서와 기본 설정을 근거로 한 것이며, 계약상 실제 데이터 처리 위치와 다를 수 있다. 운영 전 각 서비스의 DPA를 확인하는 편이 안전하다.
