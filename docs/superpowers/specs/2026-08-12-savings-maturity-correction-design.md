# 적금 만기 처리 시 마지막 달 납입 반영 - 설계

## 배경

적금을 "만기 처리"하면 [HomeClient.tsx](../../../src/app/_home/HomeClient.tsx)의
`handleSavingsMaturity`가 선택한 달 말일까지의 납입은 전부 유지하고, 이후 납입만
취소한다. 그런데 실제로는 만기 달에 납입을 하지 않고 만기가 되는 경우도 있다.
이 경우 만기 처리 후에도 그달 납입 내역이 남아 누적 납입액이 실제보다 커진다.

이미 만기 처리를 마친 적금(예: 청년도약계좌, 26.8.6 만기, 8월 미납입)을
되돌려 고칠 방법도 화면에 없다. 캘린더 선택일 목록은 읽기 전용이고,
"내역 추가/수정"의 수정 목록은 직접 입력 내역만 다룬다([HomeClient.tsx:752](../../../src/app/_home/HomeClient.tsx:752)).

추가로, 만기일을 "남은 마지막 납입일"로 다시 계산해 덮어쓰는 현재 로직
([HomeClient.tsx:2070](../../../src/app/_home/HomeClient.tsx:2070))은 마지막 달 납입을
지우면 만기일 자체가 한 달 당겨지는 부작용이 있다. 계좌에 설정된 만기일은
납입 여부와 무관하게 고정값으로 유지되어야 한다.

## 범위

- `src/app/_home/HomeClient.tsx`만 수정한다. API, 타입, DB 스키마 변경 없음.
  운영 DB 마이그레이션 없음.
- 만기 처리 확인 흐름 확장, 만기 후 되돌리기(⋮ 메뉴 재활용), 만기일 계산 규칙
  수정 세 가지를 다룬다.
- 적금 납입 내역의 범용 수정/삭제 UI는 만들지 않는다(별도 논의로 남겨둠).

## 1. 만기 처리 확인 흐름

"만기 처리" 버튼 클릭 시 확인창이 최대 두 번 뜬다.

1. 기존 그대로: `만기 처리 하시겠습니까?` (`confirm`). 취소하면 아무 것도
   바뀌지 않는다.
2. 선택한 달(만기 달)에 이미 등록된 납입 내역이 있을 때만 추가로 묻는다.
   `useAppAlert`의 `confirm(message, options)`이 `confirmText`/`cancelText`를
   지원하므로([AppAlertProvider.tsx:20](../../../src/components/app-alert/AppAlertProvider.tsx:20))
   새 다이얼로그 컴포넌트 없이 처리한다.
   - 메시지: `{YYYY}년 {M}월 납입도 하셨나요?`
   - description: `납입 안 하셨다면 {M}월 납입 내역을 지우고 만기 처리합니다.`
   - confirmText: `납입함`, cancelText: `납입 안 함`
   - 만기 달에 납입 내역이 없으면 이 단계는 건너뛰고 바로 만기 처리한다.

"납입 안 함"을 선택하면 해당 달 납입을 `cancelled` 상태로 바꾼다
(`updateSavingsPayments` 재사용, `handleSavingsPauseToggle`과 동일한 방식).
조회 쿼리가 기본으로 `cancelled`를 제외하므로([savings.ts:110](../../../src/lib/api/savings.ts:110))
캘린더 표시와 누적 납입액(`currentAmount`) 계산에 별도 처리 없이 반영된다.

레거시(문자열 메모 기반) 적금 계좌는 `cancelFutureSavingsPayments`가 적용되지
않으므로, "납입 안 함"을 선택한 경우 `deleteExpenses`로 해당 달 항목을 직접
삭제한다.

## 2. 이미 만기된 적금 되돌리기

⋮ 메뉴의 "이번 달 일시정지" 기능(`handleSavingsPauseToggle`)을 재사용하되,
선택 중인 달이 **만기된 적금의 만기 달**일 때 문구를 바꾼다.

- 평소: `이번 달 일시정지` / `이번 달 일시정지 취소`
- 만기 달(이미 만기 처리됨): `마지막 달 납입 취소` / `마지막 달 납입 복구`
- 확인창 문구도 각각에 맞게 분기한다.

로직은 기존 `handleSavingsPauseToggle`을 그대로 사용한다(취소↔복구 토글이므로
이미 요구사항을 만족함). 청년도약계좌는 8월로 달을 옮긴 뒤 ⋮ →
"마지막 달 납입 취소"로 즉시 정정할 수 있다.

만기된 적금이면서 **만기 달이 아닌 달**을 보고 있을 때는 ⋮ 메뉴에서 이 항목을
숨긴다. 만기 후 다음 달로 넘어가면 이미 끝난 적금의 납입을 되살릴 수 있는
상태가 되는 것을 막기 위함이다.

## 3. 만기일 계산 규칙 수정

`handleSavingsMaturity`가 만기일을 다시 계산하는 부분을 다음 우선순위로
변경한다.

1. 계좌에 이미 설정된 만기일이 선택한 달(만기 처리 대상 월) 안에 있으면
   그 값을 그대로 유지한다.
2. 아니면 선택한 달의 납입일(`account.paymentDay` 기준 날짜)을 사용한다.
3. 그달에 납입 자체가 없으면 선택한 달의 말일을 사용한다.

이렇게 하면 "남길 납입 내역이 없습니다" 알림으로 막히던 케이스도 자연스럽게
해소된다. 만기일 없이 운영하던 적금을 만기 처리하는 경우도 이 규칙을 따른다.

## 테스트

만기일 결정 규칙(3번)을 순수 함수로 분리해 단위 테스트를 작성한다:
- 만기일이 선택한 달 안이면 유지
- 만기일이 선택한 달 밖(또는 없음)이고 납입이 있으면 납입일 사용
- 납입도 없으면 말일 사용

나머지(확인창 분기, ⋮ 메뉴 문구/노출 조건)는 브라우저 실측으로 검증한다.
