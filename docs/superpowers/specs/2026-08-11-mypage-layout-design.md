# 마이페이지 레이아웃 개선 설계

작성일: 2026-08-11

## 배경

`feat/mypage` 브랜치에서 마이페이지를 구현한 뒤 두 가지 문제가 드러났다.

**데스크톱에서 화면이 비어 보인다.** `.mypage-layout`이 `max-width: 640px` 단일
컬럼이라, 1280px 화면에서는 오른쪽 절반이 빈 채로 카드 네 개가 세로로만 이어진다.
스크롤도 불필요하게 길다.

**회원 탈퇴의 시각적 무게가 과하다.** 탈퇴가 비밀번호 변경과 동일한 카드 형태라,
자주 쓰는 기능과 평생 한 번 쓸까 말까 한 기능이 같은 비중을 차지한다.

## 데스크톱 레이아웃

1040px을 기준으로 2열 그리드와 1열을 전환한다. 이 값은
`src/app/app/inquiries/inquiries.scss:149`가 이미 쓰고 있는 기준이므로 새 기준을
만들지 않는다.

- 왼쪽: 내 정보, 약관 동의 현황 — 둘 다 확인 성격이고 세로 길이가 짧다
- 오른쪽: 비밀번호 변경 — 입력이 셋이라 세로로 길다

두 컬럼의 높이가 자연스럽게 맞고 스크롤이 절반으로 줄어든다. 1040px 미만에서는
지금처럼 한 컬럼으로 떨어지며, 이때 순서는 내 정보 → 비밀번호 변경 → 약관 동의
현황을 유지한다. 모바일에서 보안 설정이 약관 아래로 밀리지 않게 하기 위함이다.

`max-width: 640px` 제한은 제거하고 그리드 전체에 상한을 다시 둔다.

### 검토했으나 택하지 않은 대안

**한 컬럼 유지 + 카드 내부를 가로 배치**(라벨 왼쪽, 값 오른쪽). 카드 밀도는
좋아지지만 세로로 길다는 문제 자체가 그대로 남는다.

**탭 분리**(계정/보안). 항목이 넷뿐이라 과하다.

## 회원 탈퇴 배치

카드에서 빼고, 그리드 아래에 구분선과 함께 작은 muted 텍스트 버튼으로 둔다. 누르면
그 자리에서 경고 문구와 비밀번호 입력이 인라인으로 펼쳐진다. 국내 앱들이 설정 화면
맨 아래에 작은 글씨로 회원탈퇴를 두는 패턴과 같다.

탈퇴 영역은 그리드 바깥에 있으므로 데스크톱에서도 전체 너비를 쓰며, 항상 화면
가장 아래에 온다.

펼친 뒤의 내용(삭제 대상 목록, 복구 불가 안내, 비밀번호 재인증, 탈퇴하기/취소
버튼)과 동작은 현재 구현 그대로 유지한다. 바뀌는 것은 접힌 상태의 겉모습과 위치뿐이다.

### 검토했으나 택하지 않은 대안

**별도 라우트**(`/app/mypage/withdraw`). 더 확실히 숨겨지지만 뒤로가기 처리와 라우트가
하나 더 생기는 값에 비해 얻는 것이 적다. 접힌 텍스트 링크로도 충분히 눈에 띄지 않는다.

## 범위

**수정**

- `src/app/app/mypage/mypage.scss` — 그리드, 반응형 분기, 탈퇴 영역 스타일
- `src/app/app/mypage/page.tsx` — 카드를 두 컬럼으로 나누고, 탈퇴를 그리드 밖으로
- `src/components/mypage/WithdrawCard.tsx` — 접힌 상태를 카드가 아닌 텍스트 버튼으로

**범위 제외**

- 탈퇴 확인 절차와 삭제 로직 — 동작은 그대로다
- 다른 카드들의 내부 구성
- 데모 모드 안내 카드와 페이지 헤더

## 검증

- 기존 테스트가 그대로 통과해야 한다. 특히 `WithdrawCard.test.tsx`의 "접힌 상태에서
  확인 폼이 보이지 않는다"와 "펼치면 삭제 대상이 보인다"는 겉모습이 바뀌어도 동작이
  같으므로 통과해야 한다. 토글 버튼을 텍스트 버튼으로 바꾸면서 접근성 이름(`회원 탈퇴`)이
  유지되는지 확인한다.
- `npm run lint`, `npm run test`, `npm run build`
- 1280px과 375px에서 확인한다. 1040px 전후로 2열↔1열이 전환되는지, 어느 너비에서도
  가로 스크롤이 생기지 않는지 본다.
- `HANDOFF.md` 갱신
