# 최근 직접입력 카테고리 설계

## 목적

내역 추가·수정 화면에서 사용자가 직접 입력한 카테고리를 회원별로 기억한다. 사용자는 지출·수입·저축·투자 유형마다 최근 사용한 카테고리 최대 5개를 다시 선택하거나 추천 목록에서 제거할 수 있다.

기존 가계부 내역의 `category` 값과 분석 동작은 변경하지 않는다.

## 사용자 경험

- 카테고리 선택값이 `직접 입력`일 때 입력란 위에 현재 유형의 최근 카테고리를 최근 사용순으로 최대 5개 표시한다.
- 최근 카테고리가 없으면 최근 목록 영역은 표시하지 않는다.
- 카테고리 이름을 누르면 바로 아래 텍스트 입력란에 해당 이름을 채운다. 선택만으로 최근 사용 순서를 바꾸지는 않는다.
- 각 카테고리의 삭제 버튼은 추천 목록에서만 항목을 제거한다. 해당 카테고리를 사용한 기존 가계부 내역은 유지한다.
- 직접입력 카테고리로 내역 저장이 완료되면 같은 이름을 중복 생성하지 않고 최근 사용 시각을 갱신한다.
- UI 문구 `임시 카테고리`는 지속 저장되는 동작에 맞게 `직접입력 카테고리`로 변경한다.
- 삭제 버튼에는 카테고리 이름을 포함한 접근 가능한 이름을 제공하고, 이름 선택과 삭제가 서로 간섭하지 않도록 별도 버튼으로 렌더링한다.

## 데이터 모델

Supabase에 `user_custom_categories` 테이블을 추가한다.

- `id`: UUID 기본 키
- `user_id`: `auth.users(id)` 외래 키, 회원 삭제 시 함께 삭제
- `entry_type`: `expense`, `income`, `savings`, `investment` 중 하나
- `name`: 앞뒤 공백을 제거한 표시 이름
- `last_used_at`: 마지막으로 해당 이름을 사용해 내역 저장에 성공한 시각
- `created_at`: 최초 생성 시각

회원·유형·대소문자를 정규화한 이름 조합에 고유 인덱스를 둬 중복을 방지한다. RLS 정책은 인증된 사용자가 자신의 행만 조회·삽입·수정·삭제하도록 제한한다.

테이블에는 최근 5개만 남기기 위해 오래된 행을 자동 삭제하지 않는다. 조회 시 최근 5개만 제한하면 과거 이름을 다시 사용할 때 기존 행의 순서만 갱신할 수 있고, 데이터 삭제 경쟁도 피할 수 있다. 사용자가 삭제 버튼을 누른 행만 실제로 제거한다.

## 애플리케이션 구조

`src/lib/api`에 최근 직접입력 카테고리 전용 API 모듈을 둔다.

- 유형별 최근 5개 조회
- 이름 및 유형 기준 upsert와 `last_used_at` 갱신
- 행 ID 기준 삭제

정렬·중복·최대 개수처럼 React 렌더링과 독립적인 규칙은 작은 순수 함수로 분리해 테스트한다. `HomeClient`는 로그인 모드에서는 API 결과를 상태로 보관하고, 데모 모드에서는 버전이 있는 전용 localStorage 키에 같은 형태로 보관한다.

## 데이터 흐름

1. 홈 데이터 로드와 최근 카테고리 조회를 함께 시작한다.
2. 사용자가 대카테고리 유형을 바꾸면 해당 유형의 최근 목록을 즉시 선택해 보여준다.
3. 최근 이름을 누르면 `inlineCustomCategory`만 변경한다.
4. 내역 생성 또는 수정이 성공하고 실제 선택값이 `직접 입력`이면 최근 목록을 upsert한다.
5. upsert 결과를 클라이언트 상태에도 반영해 저장 직후 최근 사용순이 갱신되도록 한다.
6. 삭제 시 서버에서 자신의 행을 삭제한 뒤 클라이언트 상태에서도 제거한다. 입력란에 같은 값이 들어 있어도 입력값과 기존 내역은 변경하지 않는다.

내역 저장이 핵심 동작이므로 최근 목록 upsert는 내역 저장 성공 이후 수행한다. 최근 목록 저장만 실패하면 내역 성공 상태는 유지하고, 사용자가 다시 저장할 필요가 없도록 비차단 안내를 표시한다.

## 오류 및 경계 조건

- 공백만 있는 이름은 기존 폼 검증으로 저장하지 않는다.
- 같은 유형에서 앞뒤 공백 또는 영문 대소문자만 다른 이름은 같은 최근 카테고리로 취급한다.
- 서로 다른 유형의 같은 이름은 각각 독립적으로 저장한다.
- 최근 목록 초기 조회 실패는 내역 화면 로드를 막지 않으며 목록만 비운 상태로 표시한다.
- 삭제 실패 시 화면 목록을 먼저 제거하지 않고 오류를 안내한다.
- 내역 수정 시 기본 제공 카테고리를 선택했다면 최근 목록을 갱신하지 않는다.

## 화면 구성

최근 목록은 입력란 위에 한 줄 또는 여러 줄로 감기는 소형 칩 목록으로 배치한다. 각 칩은 이름 선택 영역과 삭제 아이콘 버튼으로 구성한다. 모바일에서는 가로 스크롤에 의존하지 않고 줄바꿈하며, 핵심 이름과 삭제 동작을 hover 없이 확인할 수 있어야 한다.

## 검증

- 순수 함수 테스트: 유형별 분리, 최근 사용순 정렬, 5개 제한, 중복 갱신, 삭제
- API 동작 테스트: 본인 데이터 조회·upsert·삭제 요청 형태와 실패 처리
- 폼 동작 테스트: 이름 클릭 시 입력, 삭제 시 입력 및 기존 내역 유지, 직접입력 저장 성공 후 목록 갱신
- 데모 모드 테스트: 새로고침 후 유형별 목록 유지
- 수동 시각 검증: 데스크톱 및 모바일 너비에서 칩 줄바꿈, 긴 이름, 빈 상태, 삭제 버튼 접근성
- 전체 검증: `npm run lint`, `npm run test`, `npm run build`

## 범위 밖

- 기본 제공 카테고리 편집
- 최근 카테고리의 수동 정렬 또는 이름 변경
- 기존 가계부 내역에서 과거 직접입력 카테고리를 자동 이관
- 최근 목록 삭제 시 기존 가계부 내역의 카테고리 변경 또는 삭제
